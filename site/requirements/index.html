凡例

サインインしていない人、または IAT・メールの token だけを持つ人の権限です。物との関係では分けず 1 列です。

passkey でサインインした利用者が、ブラウザやアプリから操作するときの権限です。

admins に載った利用者の権限です。利用者の道では利用者と同じ値で、管理画面の道だけが違います。

client（RP・RS）が client 認証か access token で呼ぶときの権限です。

内部のきっかけで本体が操作するときの権限です。物との関係では分けず 1 列です。

値は親の行（操作）に書いています。入口ごとに値が違うマスだけ親に「≠」を書き、その値は入口の行に出しています。入口の行を押すと、条件・関係の決まり方・根拠の file:行 が開きます。

下の 2 列（物との関係）

  • 自: その物の持ち主・宛先が自分（RP なら自分の client に出た物）
  • 他: その物の持ち主・宛先が自分でない、または持ち主の無い物

記号

  • ○ 可
  • × 断
  • △ 条件つき（条件は入口の行を押すと出る）
  • － 該当しない
  • ⊘ 口無し（操作に意味はあるが、その誰が呼べる道が無い）
  • ？ 未確認
  • ≠ 入口で違う（値は入口の行に）

権限の無い人や AI がその操作をしたとき、頼んだ側にどう見えるかです。仕組みの列とは別の列です。

  • 断る: 「許されていません」とはっきり断られる（403・401）。物が在ることは相手に分かる
  • 見えない: 初めから無いもののように扱われる（404・一覧に出ない・空を返す）。在ること自体を知らせない
  • 入口で違う: 入口ごとに見え方が違う。値は入口の行に
  • 空欄: 見え方を書いていない。多くは断る場面の無い操作だが、× があるのに見え方を調べていない行も残っている

この操作を呼ぶ画面・メニューの id です。押すと画面一覧のその行へ移ります。どの画面からも呼ばれない操作は空です。

この入口の道を通すか断るかを決める設定（設定項目で効き先が ①入口 のもの）の id です。マスの値は既定の設定のときの値です。札に指を置くか押すと、設定の名・効くとき・前→後・確か／見込み・根拠が出ます。点線の札は見込みです。4 つ以上は 3 つまで出し、「+k」で残りを開きます。操作の行には出しません。

設定項目

凡例

設定がどこに効くかの 4 つの分けです。点線の札は見込み（読み口から推した分け）で、ほかは確か（読み口で確かめた）です。

  • ①入口: 物×処理×権限の表の道を通すか断るかを変える
  • ②結果: 道は通したまま、動いた結果（大きさ・待ち時間・中身など）を変える
  • ③つなぎ先: 外部システムの宛先・鍵・資格情報
  • ④土台: rust-idp を動かす土台（URL の道・中継先・起動の仕方など）

①入口は、その設定が絞る表の道の本数と、効くときです。「道 N 本」を押すと、物×処理×権限の表をその道だけに絞ります（上の「解除」で戻る）。②結果は、効く所の説明です。③④は空です。

名の頭は、設定がどこに在るかを表します。

  • env:: 環境変数
  • deploy:: 配備の形（OS・言語の版・動かし方）

値がどこに置かれるかです。

  • 環境: 起動するときの環境変数。変えるには立て直す
  • 設定 file: 配備の設定 file。変えるには配備し直す
  • DB: 動いている間に画面などから変えられる

設定が何に効くかで分けています。

  • core: rust-idp 本体の振る舞い（issuer の道・入口を開くか・ログの擬似化など）
  • infra: 本体を動かす土台（待ち受けの port・ログの深さ・配備の形）
  • connect: つなぎ先（Firestore・KMS・Resend・FAPI の試験の client の鍵など）

括弧の外は設定が効く広さ、括弧の中は変えられる人です。rust-idp の設定はすべて配備全体で、運用者が env を直して立て直します。

コードがその値を読む箇所（file:行）です。「既定」は値が置かれていないときに使う値です。

その設定が効く外部システムです。名を押すと外部システムの一覧のその行へ移ります。

その設定を変えたり読んだりする、物×処理×権限の表の操作です。id を押すと表のその行へ移ります。

外部システム

凡例

  • 外部の相手: rust-idp の外のサービス（FCM・Resend・RP の jwks_uri・FIDO の MDS）
  • 基盤: rust-idp を動かす土台（Cloud Run・Firestore・KMS・Secret Manager・メタデータサーバ）
  • 出る: rust-idp から相手を呼ぶ
  • 受ける: 相手から rust-idp に届く（webhook など）
  • 両方: 呼ぶことも、届くこともある

認証の形です。

  • OAuth: Cloud Run のサービスアカウントの access token で呼ぶ
  • 鍵: API 鍵
  • なし: 認証しない

相手が止まったとき、rust-idp の側でどう見えるかです。

  • 断: すぐ失敗として返す
  • 待つ→断: 待ったり再試行したりしてから失敗として返す
  • 黙って落ちる: 失敗を返さず、利用者に知らせないまま進む

このシステムを有効にしたり、宛先や鍵を決めたりする設定です。名を押すと設定項目のその行へ移ります。

このシステムを呼ぶ、物×処理×権限の表の操作です。id を押すと表のその行へ移ります。

畳んだ補足です。

  • 語だけで届かなかった親: 名前の字面は当たったが、呼ぶ鎖が確かめられなかった操作
  • 出口: 本体から外へ出る所（file:行）
  • 本体の外: 本体を通らずに外へ出る所と、その理由

外部の物×処理×権限

rust-idp が外部の相手と基盤の何を読み・作り・消すかと、それを誰の権限で行うかの表です。1 行は外部の物 1 つと処理 1 つの組です。答えるのは rust-idp が外部に何をするかで、外部のサービスの中の動きは扱いません。

凡例

rust-idp の側でその処理を行う入口（AI の道具名・API の道・cron・webhook の受け口など）と、コードの場所（file:行）です。

rust-idp の側で、その呼び出しを許す・止める判定（権限・設定・役）です。物×処理×権限の表の操作に結べたものは id を並べます。id を押すと表のその行へ移ります。

誰のトークンで呼ぶか（組織の鍵・本人の OAuth・仕組み）と、求める scope、外部の側で要る権限です。外部の側の権限は外部を呼ばないと確かめられないので、コードと設定から読んだ説明です。

結果が入る rust-idp の物と、そこで誰に見えるかです。入らないものは「入らない」と書きます。

  • 確か: コードで、呼び出しから関門まで辿れた
  • 見込み: 名前や型から推した。点線の札で示します

手順

「〜できるようにするには、誰に何を頼み、自分は何を順にするか」に答える一覧です。目的（T-00 の形）ごとに段（T-00-1 の形）を並べ、段ごとに 6 覧の行を名指します。どの段も本番では通しておらず、コードと画面の案内文から組みました。運用者は権限の列を持たないので、運用者の段は操作を名指しません。

データモデル

rust-idp の Firestore のコレクションと、コレクションどうしのつながりの一覧です。gcp の feature 無しで build した binary は、同じコレクションをメモリに置きます。1 行はコレクション 1 つで、id（D-001 の形）はほかの一覧から指すための番号です。Firestore には目録が無いので、コードが渡すコレクションの名を洗って 25 行にし、環境変数から積む静的な client を外の物として 1 行足しました。

-- 親が消えると一緒に消える（DB が縛る） -> 指している間は相手を消せない（DB が縛る） ~> 指すが DB は縛らない（相手が消えても残る） 宣言 DB に外部キーがある コード 外部キーは無く、コードが id を突き合わせているのを確かめた

凡例

表の番号（D-001 の形）です。ほかの一覧から表を指すときに使います。番号は台帳で固定し、表が増えても付け直しません。消えた表の番号は使い回しません。

Firestore のコレクションの名です。コードの名のまま載せています。

  • コレクション: Firestore のコレクション（サブコレクションは無い）
  • 外の物: Firestore に無いが、id が指す相手（環境変数から積む静的な client）

このコレクションを読む・書く、物×処理×権限の表の操作の id です。押すとその行へ移ります。

  • 実線の札: 入口からコレクションに触る関数まで、コードで辿れた
  • 点線の札: 名前が合うだけ、または helper が 3 段以上
  • 横断: 監査・管理者の名簿・一度きりの印。多くの操作が通るので札にしない

表の列の数です。

行を 1 つに決める列（主キー）です。複数の列の組のときはコンマで並べます。

この表の列が、ほかの表を指すつながりです。1 行が 1 つのつながりで、「記号・相手の表・via 指す列」の順に並びます。相手の表を押すと、その表の行へ移ります。

  • -- 親が消えると一緒に消える（DB が縛る）
  • -> 指している間は相手を消せない（DB が縛る）
  • ~> 指すが DB は縛らない（相手が消えても残る）
  • -- 子: 逆向きの印で、この表が親です。相手の表の行が、この表の行と一緒に消えます
  • 宣言 DB に外部キーがある
  • コード 外部キーは無く、コードが id を突き合わせているのを確かめた
  • 相手が「a|b」のように並ぶのは、値によって指す相手が変わる列です（範囲など）

札や行に指を置くと、確かめた根拠が出るものがあります。

id を持つが、つながりとしては書かない列と、その理由です（2 種の値が混ざる、書く所が無い、など）。黙って落とさず、ここに名指しています。

日時を整数のミリ秒で持つ列の数です。数に指を置くと列の名が出ます。

索引の名前・降順・CHECK の名前など、DB の物理の性質の数です（記法の @pg の行）。数に指を置くと中身が出ます。

いまの記法では書けない物と、その理由です（次元を決めない vector など）。

押すと、その表を DMNotation の記法で書いた行がそのまま開きます。もう一度押すと閉じます。
